## 1. Project Vision & Architecture
**CineClaw** is a modular, self-hosted home cinema and streaming platform.
- **Repository Architecture**: The main repository (`cineclaw`) is a lightweight deployment and orchestration entry point (`install.sh`, `docker-compose.yml`). All components are isolated submodules under the `cineclaw` GitHub organization:
  - `imdb-indexer`: Tantivy search engine, TMDB seasons proxy, zero-disk redb poster caching.
  - `tracker-proxy`: Multi-tracker scraper/dedup, TorrServer orchestrator, pure-Go SQLite playback & watchlist store.
  - `frontend`: React 19 cinema UI, HLS/direct streaming, swarms bitrates, quick play.
  - `torrserver-gst`: TorrServer-Turbo BitTorrent streaming engine with GStreamer 1.24 remuxing.
  - `cineclaw-ai`: Critics score aggregation (RT, Metacritic, OMDb) and OpenRouter LLM consensus.
  - `android-tv`: Native Android TV client in Jetpack Compose for TV with Media3 ExoPlayer.
  - `apple-tv`: Native tvOS client in Swift 6 / SwiftUI with KSPlayer (FFmpeg + Metal).
- **Zero-Compilation Deployments**: Production deployments pull official pre-built multi-arch images (`linux/amd64`, `linux/arm64`) from GHCR (`ghcr.io/cineclaw/*`).

## 3. Operations Cheatsheet

### Multi-Arch Building & GHCR Publishing (`Makefile`)
```bash
# Build and publish all microservices to GHCR (amd64 + arm64)
make publish-all VERSION=1.2.0

# Build and publish individual services
make publish-indexer VERSION=1.2.0
make publish-tracker VERSION=1.2.0
make publish-frontend VERSION=1.2.0
make publish-ai VERSION=1.2.0
make publish-torrserver VERSION=1.2.0

# Fast local builds for host architecture
make build-local
```

```bash
# Start with local source builds
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

### Frontend (`frontend` - Vite / React 19)
```bash
cd frontend
# Start local dev server (port 3000)
npm run dev

# Check TypeScript & production build
npm run build
```

### Torrent Streaming Engine (`torrserver`)
```bash
# Restart TorrServer container
docker compose restart torrserver

# View streaming & transcode logs
docker compose logs -f torrserver
```

## 4. Critical Invariants & Rules (Strictly Enforced)

1. **NEVER delete `./data/`**:
   - `data/tracker-proxy/cache/cache.db` stores bbolt caches (`imdb_cache`, `topic_hashes`).
   - `data/tracker-proxy/config.yaml` contains tracker credentials.
   - `data/fdb/` contains the IMDb Tantivy search index.
   - `data/imdb-indexer/poster_paths.redb` contains redb lookup table for TMDB relative poster and backdrop paths.
   - `data/media/` contains source JSON stubs and FUSE virtual mount points.
2. **Trackers Rate Limiting & Empty Query Prevention**:
   - NNM-Club throws Cloudflare `503` if hit with $>2$ concurrent requests. Always enforce semaphores and $\ge 75$ms pacing.
   - RuTracker requires FlareSolverr session tokens (`bb_session`).
   - Trackers DO NOT index or search by IMDb ID (`tt...`). Querying trackers with empty `q=""` is strictly forbidden (aborts immediately in `aggregator.Search`) to prevent tracker homepage dumps from poisoning the cache. When `q` is omitted, `tracker-proxy` auto-resolves the title via `imdb-indexer`.
3. **Cross-Tracker Deduplication**:
   - Size clustering tolerance is strictly $\pm 0.105\text{ GB}$ ($\pm 0.1\text{ GB}$ rounded to 1 decimal place).
   - Only merge when verified by InfoHash comparison.
   - Combined releases must merge seeds ($\sum \text{seeds}$) and inject all official announce URLs into the synthesized magnet.
4. **TorrServer & Media Database Invariants**:
   - Media playback state is persisted in pure-Go SQLite (`data/tracker-proxy/cineclaw.db`).
   - Watch progress preservation rule: when mounting alternative quality/releases or switching qualities, existing playback position (`position_seconds`) MUST NEVER be zero-wiped (`COALESCE` guard).
   - Multi-season pack mapping invariant: In series torrents containing multiple seasons (`isMultiSeason == true`), cross-season episode matching is strictly forbidden. Files are resolved via a 4-pass hierarchy (exact range match, in-season token/continuous offset/natural order sort). An episode for Season $N$ must NEVER fall back to Season 1.
   - TorrServer container runs custom distribution with GStreamer 1.24 (`torrserver-gst`) enabling instant track probing (`/gst/:hash/probe`) and HLS remuxing (`/torr/gst/<hash>/master.m3u8`).
   - External player stream links direct to port `8092` (`http://<host>:8092/stream?link=<hash>&index=<idx>&play`).
5. **Zero-Disk Image Architecture & Direct Edge TMDB CDN Streaming**:
   - No image files (JPEG, WebP, PNG) are downloaded to server or host disk. File-based poster caches are completely removed.
   - No HTTP 307 temporary redirects for image endpoints. Clients (React 19 & Android TV) stream directly from TMDB's edge Cloudflare CDN (`https://image.tmdb.org/t/p/{size}{path}`).
   - Backend microservices store ONLY the 33-byte relative path (e.g. `/piQXcdOGgv1O9HQ07pI0tnjkGJw.jpg`) in `redb` (`poster_paths.redb`), resolving in $<1$µs.
6. **Context Window Hygiene**:
   - Do not dump hundreds of lines of code or raw HTML into user messages. Keep responses concise and focused.
7. **Documentation Maintenance (Strict Requirement)**:
   - Any agent modifying architecture, adding services/ports, changing scraper logic, updating endpoints, or altering UI features **MUST** immediately update `AGENTS.md` and the corresponding documents in `docs/`. Never leave documentation stale or out of sync with the codebase.
